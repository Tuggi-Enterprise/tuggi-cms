## 🔄 User Flows

### Flow 1: Criar Cliente (Admin)
```
/dashboard/admin/clients
         ↓
    [New Client Button]
         ↓
/dashboard/admin/clients/new
         ↓
  ClientFormAdmin (POST /api/admin/clients)
         ↓
[Success redirect]
         ↓
/dashboard/admin/clients/[id]
```

### Flow 2: Editar Cliente (Admin)
```
/dashboard/admin/clients
         ↓
    [Edit Button]
         ↓
/dashboard/admin/clients/[id]/edit
         ↓
  ClientFormAdmin (PATCH /api/admin/clients/[id])
         ↓
[Success redirect]
         ↓
/dashboard/admin/clients/[id]
```

### Flow 3: Criar Usuário (Admin)
```
/dashboard/admin/users
         ↓
    [New User Button]
         ↓
/dashboard/admin/users/new
         ↓
  UserFormAdmin (POST /api/admin/users)
  - Select role
  - If role=client, select client
  - Set password
         ↓
[Success redirect]
         ↓
/dashboard/admin/users
```

### Flow 4: Vincular Usuário a Cliente (Admin)
```
/dashboard/admin/clients/[id]
         ↓
  [Add User Button]
         ↓
  ClientDetails component
  - Show available users (not linked)
  - Select client_role (owner|manager|viewer)
         ↓
  POST /api/admin/users/[userId]/link-client
         ↓
  Linked users table updated
```

## 📋 API Endpoints Summary

### Clients Endpoints
```
GET    /api/admin/clients
       ├─ Query: page, limit, search, status
       └─ Returns: clients[], pagination

POST   /api/admin/clients
       ├─ Body: name, email, phone, ...
       └─ Returns: created client

GET    /api/admin/clients/:clientId
       └─ Returns: client with users_count

PATCH  /api/admin/clients/:clientId
       ├─ Body: updatable fields (no client_id)
       └─ Returns: updated client

DELETE /api/admin/clients/:clientId
       ├─ Validation: no linked users
       └─ Returns: success message
```

### Users Endpoints
```
GET    /api/admin/users
       ├─ Query: page, limit, search, role, is_active
       └─ Returns: users[], pagination

POST   /api/admin/users
       ├─ Body: email, full_name, password, role, client_id, ...
       └─ Returns: created user

GET    /api/admin/users/:userId
       └─ Returns: user object

PATCH  /api/admin/users/:userId
       ├─ Body: email, full_name, is_active, ...
       ├─ Restricted: role, client_id (immutable)
       └─ Returns: updated user

DELETE /api/admin/users/:userId
       └─ Returns: success message

POST   /api/admin/users/:userId/reset-password
       ├─ Body: password
       └─ Returns: success message

POST   /api/admin/users/:userId/link-client
       ├─ Body: client_id, client_role
       └─ Returns: created link

DELETE /api/admin/users/:userId/link-client?client_id=...
       └─ Returns: success message
```

## 🔐 Security Model

```
Authentication
    ↓
Check session.user exists
    ↓
Lookup cms_user by email
    ↓
Verify role = 'admin'
    ↓
Verify is_active = true
    ↓
Allow access to admin endpoints
    ↓
DENY (403) if not admin
```

## 📊 Data Relationships

```
clients
  ├─ id (PK)
  ├─ name
  ├─ email (UNIQUE)
  ├─ status (pending|approved|rejected)
  ├─ cms_user_id (FK→cms_users, ONE PRIMARY CONTACT)
  └─ ...

cms_users
  ├─ id (PK)
  ├─ email (UNIQUE)
  ├─ full_name
  ├─ role (admin|client|editor|viewer)
  ├─ client_id (FK→clients, ONLY IF role='client', IMMUTABLE)
  └─ ...

client_cms_users (Junction)
  ├─ id (PK)
  ├─ client_id (FK→clients)
  ├─ cms_user_id (FK→cms_users)
  ├─ client_role (owner|manager|viewer)
  └─ UNIQUE(client_id, cms_user_id)
```

## 🎯 Validation Rules

```
CREATE CLIENT
  ✓ name required
  ✓ email required & unique
  ✓ status must be valid (pending|approved|rejected)

UPDATE CLIENT
  ✓ email unique (if changed)
  ✓ cannot change cms_user_id

DELETE CLIENT
  ✓ cannot delete if client_cms_users count > 0

CREATE USER
  ✓ email required & unique
  ✓ full_name required
  ✓ password required (if creating)
  ✓ role must be valid
  ✓ if role=client, client_id required

UPDATE USER
  ✓ email unique (if changed)
  ✓ CANNOT change role
  ✓ CANNOT change client_id

DELETE USER
  ✓ no constraints (cascades handled by FK)

LINK USER TO CLIENT
  ✓ user must exist
  ✓ client must exist
  ✓ unique constraint (client_id, cms_user_id)
  ✓ client_role must be valid (owner|manager|viewer)
```

## 📝 Notes

1. **Email as identifier:** Email is unique and used in table display, but id is used for FK relations
2. **Role immutability:** User role and client_id cannot be changed after creation - by design
3. **Client ownership:** clients.cms_user_id is the primary contact, client_cms_users is the full team
4. **Auth integration:** cms_users record created when auth user is created via admin endpoint
5. **Password reset:** Separate endpoint from edit - allows admin to reset without knowing current
6. **Client selection:** When creating client user, client is selected from approved clients only
