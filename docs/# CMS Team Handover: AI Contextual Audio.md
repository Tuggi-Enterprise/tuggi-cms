# CMS Team Handover: AI Contextual Audio Guide

## 1. Overview & Purpose
We have transformed the Tuggi mobile app into an **AI-First, Offline-Resilient Audio Guide**.
The goal is to provide **dynamic, context-aware narration** (e.g., "On your left, you'll see...") generated by AI, while maintaining **zero latency** at the moment the user passes a Point of Interest (POI).

To achieve this, the mobile app now implements a **"Two-Stage Prefetch"** system that requests content *before* the user arrives. We need the CMS/Backend team to implement the server-side logic to support this.

## 2. What We Have Implemented (Mobile App)
The mobile app update (v0.0.28+) includes:
*   **Smart "Cone" Detection**: The app identifies POIs 400m ahead using a ±35° viewing angle.
*   **2-Stage Polling**:
    *   **Stage 1 (400m)**: Requests **Text Generation** (warms up the server).
    *   **Stage 2 (250m)**: Requests **Audio Generation** (TTS).
*   **Silent Fallback**: If the backend fails or returns 404/500, the app silently falls back to the existing static audio files.
*   **Database Updates**: We added `facts_pack_json` to `attraction_descriptions` and created a `cache_narrations` table.

## 3. What We Need From You (Backend)

We need you to implement a Supabase Edge Function named **`generate-contextual-narration`**.

### 3.1. API Contract
**Function Name:** `generate-contextual-narration`

#### Request Body (JSON)
```json
{
  "action": "generate_text" | "generate_audio",
  "poi_id": "uuid-string",
  "travel_mode": "drive" | "walk",
  "user_context": {
    "location": { "latitude": 0.0, "longitude": 0.0 },
    "speed": 0.0, // km/h
    "heading": 0.0, // degrees
    "last_pois": [], // array of recently visited POI IDs
    "language": "pt-BR"
  },
  "text_content": "..." // Optional: Sent ONLY in 'generate_audio' request to skip LLM re-generation
}
```

#### Response Body (JSON)
```json
{
  "success": true,
  "data": {
    "text_content": "Here is the generated text...",
    "audio_url": "https://storage.googleapis.com/.../file.mp3", // Only for 'generate_audio'
    "expires_at": "ISO-8601-Timestamp"
  }
}
```

### 3.2. Implementation Logic (The "Warm Up" Strategy)
To ensure <1s latency for audio generation, we designed the flow to reuse resources:

1.  **Handling `action: 'generate_text'`**:
    *   **Input**: User is 400m away.
    *   **Task**: Use LLM (e.g., Gemini) to generate narration based on `facts_pack_json` and `user_context`.
    *   **Output**: Return `text_content`.
    *   *Note: Cold start latency (2-3s) is acceptable here.*

2.  **Handling `action: 'generate_audio'`**:
    *   **Input**: User is 250m away. Client sends back the `text_content` it received in Stage 1.
    *   **Task**: Convert `text_content` to Speech (Google TTS / OpenAI).
    *   **Output**: Upload MP3 to storage, return `audio_url`.
    *   *Note: This MUST be fast. Reusing the text skips the expensive LLM step.*

### 3.3. Server-Side Caching (Crucial)
To save costs and improve speed, please implement **Context Caching** using the new `cache_narrations` table:
*   **Key**: Create a hash of `{poi_id, travel_mode, approximate_direction, language}`.
*   **Logic**: Before calling AI, check if a valid narration exists for this "Context Signature". If yes, return the cached URL.
