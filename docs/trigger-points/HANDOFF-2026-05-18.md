## O que foi feito nesta sessão

### Tier 1 — Correções bloqueantes

**1.1 Geofence radius fix** (`predictor.buildGeofenceTriggerPoint`)
- Antes: `safetyRadius = max(500, fanMax)` → pra LaGuardia (polígono 2km, fan 300m) o radius ficava 500m, menor que o polígono → app nunca disparava geofence
- Agora: `safetyRadius = max(500, fanMax, polygonBoundingRadius)` onde `polygonBoundingRadius = max(dist(center, vertex))` pra todos os vértices
- Resultado: LaGuardia tem radius 2.1km, engloba todos os terminais

**1.2 Atomic replace_all** (`trigger-point-saving.ts`)
- Antes: DELETE + INSERT separados → se INSERT falha, POI fica com 0 TPs em prod
- Agora: `supabase.rpc('replace_trigger_points_atomic', ...)` → tudo ou nada via BEGIN/COMMIT no PostgreSQL
- Migration: `supabase/migrations/20260518_replace_trigger_points_atomic_rpc.sql`
- Aplicar com: `supabase migration up`

**1.3 N+1 query fix** (`migration-service.ts`)
- `shouldProcessPOIBatch(uuid_ids)`: 2 queries no total (lista de IDs com TPs + lista com errors) em vez de 1 por POI
- `migrate-batch/route.ts` e `migrate-stream/route.ts` usam o método batch

**1.4 TPLogger configurável** (`utils/logger.ts`)
- `TP_LOG_LEVEL=silent|error|info|debug` (default `info`)
- Em produção: `TP_LOG_LEVEL=error` reduz ~95% do volume de logs

### Tier 2 — Estrutural

**2.1 IDs determinísticos** (`utils/deterministic.ts`)
- `deterministicTPId(attractionId, type, lat, lng)`: SHA-256 truncado pra 8 chars + prefix
- `seededRng(seed)`: mulberry32 PRNG para sample points determinísticos
- Mesma entrada → mesma saída entre execuções. Facilita diff entre versões do motor.

**2.2 Geographic context cache** (`boundary-detector.ts`, `trigger-point-predictor.ts`)
- `BoundaryData.cachedContext`: detector computa contexto durante classification e armazena no boundary
- Predictor reutiliza o contexto cached, evitando 2-4× recomputação de `analyzeGeographicContext`
- Economia: ~1-2 calls OSM por POI

**2.3 LRU cache com TTL** (`utils/lru-cache.ts`)
- `LRUCacheWithTTL<K, V>(maxEntries, ttlMs)` com eviction FIFO quando cheio
- Substituiu 4 `Map<>` sem limite: `surroundingHeightCache`, `elevationCache` (ganhou TTL 24h)
- `maxEntries=1000` por cache (cobre cidade inteira sem OOM)

**2.4 Memory caps por distância** (`config/trigger-points-config.ts`)
- `TRIGGER_POINTS_CONSTANTS.memory.maxBuildingsPerPOI = 5000`
- `TRIGGER_POINTS_CONSTANTS.memory.maxStreetsPerPOI = 8000`
- Sort por distância antes de slice → mantém os mais próximos (qualidade > memória)
- Log: `"Memory cap: trimmed N→M"` quando dispara (JFK ~27k buildings → 5k)

**2.5 defaultHouseHeight 10m** (era 6m)
- Fallback conservador para buildings sem `height` nem `building:levels`
- Menos ray-cast leaks em cidades com baixa cobertura de dados de altura no OSM

**Fresta B — skip Camada 1 pra POIs grandes** (`predictor.useContainingBuildingHeight`)
- Skip quando `boundary.area_m2 > 5000 m²`
- Pra aeroportos/parques, o POI **é** a área — herdar altura de um prédio do centroide inflava o fan. JFK pegava terminal (30m) em vez de pista (0m).

**Fresta C — interior grid sampling pra POIs gigantes** (`visibility-map-builder.ts`)
- Quando `boundary.area_m2 > 1 km²`: adiciona até 16 pontos em grade 4×4 dentro do polígono
- Interior points capturam obstáculos internos (terminais bloqueando visão de outros terminais)

**SRTM base elevation regional** (`trigger-point-predictor.ts`)
- Horizon formula: `max(300, min(15000, effectiveHeight × 15))`
- `effectiveHeight = max(poi_height, poi_height + elevDiff_if_>100m)` onde `elevDiff` é calculado via SRTM em 4 pontos cardeais a ~2km
- Antes: horizon do AMNH (~5m) era 75m, muito baixo. Agora com base regional correta: ~300m
